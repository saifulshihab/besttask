# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

BestTask: project and task management. Two separate npm projects share this repo: the Express API at the root (`src/`) and the Vite + React web app in `web/`, each with its own `package.json`, lockfile, ESLint config and CI job. Who may do what is specified in `FEATURE_MATRIX.md` (stable feature IDs such as T08, U06); the API enforces it, so change the matrix and the API together. Record user-visible changes in the `Unreleased` section of `CHANGELOG.md`.

## Commands

Development runs in Docker Compose against the hosted Prisma Postgres database configured in `.env` (see `.env.example`); the API is on `:4000`, the web app on `:3100`. `node_modules` live in Compose volumes, so run project commands inside the containers (`docker compose exec api …`, `docker compose exec web …`) or after `npm ci` on the host.

```bash
docker compose up -d                       # API (tsx watch) + web (Vite dev server)
docker compose exec api npm run db:migrate # apply committed migrations

# API (repo root)
npm run typecheck && npm run lint && npm run build
npm run db:generate                        # after changing prisma/schema.prisma
npm run db:migrate:dev -- --name <name>    # new migration; needs SHADOW_DATABASE_URL set to a disposable database
npm run test:integration                   # needs the API running on :4000

# Web (cd web)
npm run typecheck && npm run lint && npm run build
```

- The integration test (`tests/integration.mjs`) is one end-to-end script against a running API, not a test runner: there is no way to run a single case. It creates and deletes its own uniquely named accounts and never resets the database. `BESTTASK_TEST_API` points it at another API; `BESTTASK_TEST_RESTART=1` adds a check that restarts the `api` container mid-Undo. CI runs it against a throwaway Postgres 16 with the compiled API.
- The web app has no unit tests; its checks are typecheck, lint and build.
- **Never edit a migration that has been applied anywhere.** `prisma migrate deploy` skips migrations by name, so an edited migration silently never reaches databases that already ran it. Schema changes always go in a new migration. The production container runs `prisma migrate deploy` on start.
- `web/src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin from `web/src/routes/` and committed (CI typechecks against it). Do not edit it by hand; `.gitattributes` keeps it LF.

## API architecture (`src/`)

- Each module in `src/modules/<name>/` has `*.routes.ts` → `*.controller.ts` → `*.service.ts`, plus `*.schema.ts` (Zod). Controllers use `route()` from `src/lib/http.ts`: it parses body, query and params with the given schemas and sends whatever the handler returns as JSON (`undefined` → 204). `src/routes.ts` mounts nested routers before shorter prefixes on purpose.
- **Services never see `req`/`res`.** They take an explicit `actor` (`actorOf(req)`) and do their own authorization, so a future MCP layer can call them with the same checks. Authorization helpers:
  - `requireMembership` (`src/lib/rbac.ts`) for workspace-level access; the owner is `workspace.ownerId`, there is exactly one.
  - `projectScope` / `taskScope` (`src/lib/scope.ts`) load the project, workspace membership and project assignment in one query (Prisma `relationJoins`) and enforce a minimum role. Admin/Member roles exist only per project; anything inaccessible is a **404**, not 403. Archived projects reject writes.
  - `visibleProjects` filters lists to projects the actor is assigned to (the owner sees all).
- Errors come from `src/lib/errors.ts` (`badRequest`, `forbidden`, `notFound`, `conflict`) and are mapped by `middleware/errorHandler.ts` (Prisma `P2002` → 409). A wrong confirmation password returns 400, not 401: the web client treats 401 as an expired session and refreshes and retries.
- **Deletion is recoverable for six seconds.** Tasks, labels, chat channels, projects and memberships are soft-deleted (`deletedAt`) through `scheduleDeletion` in `src/lib/recovery.ts`, which writes a `Recovery` row; `POST /recovery/:id/undo` restores it, and a timer in `server.ts` runs `purgeExpired` to hard-delete expired ones. Queries must exclude `deletedAt` rows.
- **Activity** (`recordActivity`, `src/lib/activity.ts`) is the audit trail. Metadata carries what the feed needs to describe an event (`title`, `changes: { field: { from, to } }`, names); `activity.service.ts` resolves the people mentioned. Feed wording and event types are derived on the client in `web/src/lib/activity.ts`.
- **Notifications** (`notify` / `taskFollowers`, `src/lib/notifications.ts`) are written alongside the action, never for the actor's own action, and access is re-checked every time they are read.
- **Chat is live only.** Channels are stored (`chat` module); messages are relayed over socket.io and never written anywhere. `src/lib/realtime.ts` owns the socket server, attached to the HTTP server in `server.ts`: the handshake is `{ token, workspaceId }`, rooms are `project:<id>` (everyone who can open an active project) and `member:<workspaceId>:<userId>` (one person's tabs, for DMs), and `chat.socket.ts` registers the chat events, which call `chat.service.ts` like any controller. **Anything that grants or revokes project access must call `realtime.syncWorkspace`** (membership, archive, ownership, recovery already do), and session changes call `dropSession` / `dropUser`; a sweep every minute re-checks sessions and access as a backstop. Connections live in process memory, so this assumes one API instance.
- **Task order**: `position` is a per-project counter on create (new tasks sort last). `POST /tasks/:id/move { status, beforeId }` renumbers the target column inside a transaction that locks the project row. Any other status change puts the task at the end of its new column.
- `src/lib/prisma.ts` tunes the pg pool for the hosted database (long idle timeout, keep-alive, warm-up on listen); `DATABASE_URL` is the pooled connection, `DIRECT_URL` the direct one used by the Prisma CLI.

## Web architecture (`web/`)

- Single-page app: TanStack Router (file-based routes in `src/routes/`) + TanStack Query. Signed-in pages live under the pathless `_app` route, whose `beforeLoad` redirects to `/login`. Route loaders prefetch with `ensureQueryData`, and links preload on hover.
- The API client (`src/lib/api.ts`) sends `Authorization: Bearer` from `localStorage` (`bt_*` keys, `src/lib/auth.ts`) and refreshes once on 401. Network failures become `ApiError` with status 0. In development Vite proxies `/api` to the API; production uses `VITE_API_URL` (read at build time).
- **Query keys come only from `keys` in `src/lib/queries.ts`.** Mutations live in `src/lib/*-mutations.ts`, update the cache optimistically where the result is certain, roll back on error, and invalidate the narrowest key; never call a bare `invalidateQueries()`. `src/lib/query-client.ts` also detects lost access: when a project or workspace that loaded fine starts returning 403/404, its cache is reset so the route's `RouteError` replaces the stale page.
- Toasts go through `src/lib/toast.ts` (`toast`, `toastError`, `undoToast`); only it and `components/ui/toaster.tsx` import Sonner.
- UI primitives in `src/components/ui/` are hand-written on Base UI (no shadcn), including custom Select, DatePicker (react-day-picker), color picker (react-colorful), Checkbox, Tooltip and NumberStepper. Native form controls are deliberately avoided. Design tokens are Tailwind 4 `@theme` variables in `src/styles.css` (dark mode under `:root[data-theme="dark"]`, applied before first paint by a script in `index.html`) plus domain constants (statuses, priorities, label and project colors) in `src/lib/design.ts`.
- The API embeds people (task assignee, comment author, activity actor) without their photo, because photos are inline image data. `AvatarDirectory` (`components/ui/avatar-directory.tsx`) fills them in from member lists the app already loaded.
- **Chat** (`src/lib/chat.tsx`): `ChatProvider`, mounted per workspace in the workspace layout, owns the socket.io connection and an in-memory store (`useSyncExternalStore`) of messages, unread counts and presence; messages are deliberately not in TanStack Query and vanish on reload. It hands each refreshed access token to the socket (`session:refresh`, via `onSessionChange`) and retries a refused handshake once through `refreshOnce` in `api.ts`. Channels are an ordinary query (`keys.projectChannels`, mutations in `chat-mutations.ts`) that the socket's `channels:changed` invalidates. Conversation ids in URLs are a channel id or `dm-<userId>`; the chat route skips `ProjectHeader` and fills the window. Vite proxies `/socket.io` (with `ws`) like `/api`.
- Below 768px (`useIsMobile`) the project board renders `components/mobile/mobile-project.tsx` instead of the desktop board; other pages render full width.
- The board (`components/tasks/task-board.tsx`) uses dnd-kit (core + sortable). In the default "Manual" sort, a drop calls the move endpoint with the card it lands before; with any other sort, a drop only changes the column.
